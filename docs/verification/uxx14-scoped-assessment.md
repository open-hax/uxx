## Execution and refusal boundaries

The `issue_comment` handler must first be reviewed and merged into the default
branch. GitHub runs the default-branch workflow; a PR-only route cannot respond.
The parent then posts a fresh canonical two-line writer proposal separately
from the trigger:

```text
/opencode assess-actionability 68eeefdca9d840571e2dec911085b782dc5c4ed2 PRRT_kwDOR5O5HM6omklO comment4172775340 proposal<NATIVE_PROPOSAL_ID>
```

The trigger is an unedited, exact native comment by the same currently verified
repository writer as the latest proposal. The PR must remain open, non-draft,
public and in the same repository. All conversation comments and their enclosing
reviews are manifest-bound; missing data, truncated conversation pagination,
duplicate comment inventory entries and API errors fail closed. New or edited
proposals, changed head/base/context, existing native assessments and malformed
commands prevent a model invocation or publication. Existing assessment
reconciliation belongs to canonical pr-flow and the parent; this one-shot route
does not resurrect or overwrite old evidence.

The read/model job has read-only GitHub permissions and no OIDC permission. It
passes the entire fatal-UTF8-decoded Git diff, complete native context and
proposal into the prompt, without preview truncation. A diff above one MiB or
an input artifact above two MiB refuses this bounded route. Sensitive changed
paths refuse before inference. The isolated source snapshot uses trusted base
instructions; proposed instructions stay untrusted data. The model independently
chooses informational, finding or uncertain and supplies its reason and scoped
evidence. The prompt never prefills a favorable verdict. Missing or mismatched
head/hash/file coverage, nonempty inline-review output or an invalid protocol
refuses publication.

The publisher runs on a fresh runner without a model secret or model process.
It independently recollects native context and the Git-bound full input before
App mint, then again inside the App callback before its sole write: creating
one issue comment. It reads back the actual native ID, author tuple, body,
chronology and PR URL and recollects context/comments after publication before
calling canonical disposition. A concurrent change refuses qualification. A
failed post/readback is not automatically retried because a comment may exist;
the parent must inspect the preserved native state. It does not edit comments,
resolve conversations, set labels, write board state or publish a PR approval.
Finding and uncertain results remain findings. Native readback alone cannot
settle Uxx14; canonical writerHandled and other existing obligations remain.

All actions in the three new jobs use immutable SHAs verified against current
Proxx workflow source, including artifact download. The original
issue-triage/daily job bytes, triggers/conditions, provider strings and permissions
are unchanged. Their pre-existing availability is not repaired or claimed by
this assessment-only slice.
