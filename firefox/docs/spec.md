# Spec — Uxx Monokai Firefox Extension (code-level)

**Status:** v1 — implementation contract derived from `design.md` (v2, PASS-WITH-FIXES).
**Date:** 2026-10-30
**License:** GPL-3.0-or-later (design §13).

This document is precise enough to implement module-by-module without
re-deriving design decisions. Where the design left a number unspecified, this
spec pins it and says so (`spec-pinned`). Where this spec tightens the design,
it says `spec-refinement`. Nothing here may contradict `design.md`; if it
appears to, `design.md` wins and this file is wrong — fix this file.

| Perf/robustness constants | `design.md` §10 (numbers pinned in §5 below) |

**Invariant (every module):** every color *emitted* (written to a marker,
sheet, or theme object) is a value present in `themePacks.monokai` or a
`withAlpha` derivation of one (design §7 wording — alpha-composites of two
pack tokens are computed for *contrast checking only*, never emitted). No HSL
transforms, no invented hues (design §2, §7).

## 3. `src/lib/color.js` — color math (pure, no DOM)

All functions are pure and take/return plain objects. `Color` =
`{ r: 0..255, g: 0..255, b: 0..255, a: 0..1 }` (floats allowed).

```js
parseColor(input)            // string → Color | null
  // accepts: #rgb #rgba #rrggbb #rrggbbaa; rgb()/rgba() incl. space syntax,
  // slash syntax, and %; hsl()/hsla(); 'transparent'; the full CSS named-color
  // table (static const in this file — design §12 "every CSS color syntax").
  // Anything else → null (caller skips: design §10 bail-out).
formatColor(color)           // Color → 'rgba(r, g, b, a)' with ints rounded, a trimmed
isTransparent(color)         // a === 0
composite(fg, bg)            // source-over; result alpha = fg.a + bg.a*(1-fg.a)
luminance(color)             // WCAG 2.x relative luminance, full sRGB linearization
                             // (research B §4.1; explicitly NOT getSRGBLightness).
                             // Preconditions: color.a === 1 (composite first).
contrast(fg, bg)             // composite(fg, bg) over opaque bg → (L1+.05)/(L2+.05), ≥1
toHsl(color)                 // → { h: 0..360, s: 0..1, l: 0..1 }
hueBucket(color)             // §8.4 table exactly:
                             //   S<0.10 → 'neutral'
                             //   [345,360)∪[0,15) → 'red'  [15,45) → 'orange'
                             //   [45,70) → 'yellow' [70,165) → 'green'
                             //   [165,260) → 'cyan-blue' [260,345) → 'purple-magenta'
deltaE2000(c1, c2)           // CIEDE2000 (research B's distinct-color metric)
thresholdFor({ sizeClass, muted, nonText, prefersMore })
                             // nonText → 3 (design §8.3.2's 3:1 for non-text
                             //   UI: border/outline emissions — border-focus,
                             //   focus; round-3 M1)
                             // else prefersMore → 7; else large|muted → 3;
                             // else 4.5 (design §8.3.2; muted = text-muted,
                             // text-faint, ::placeholder)
sizeClassOf(fontSizePx, fontWeight)
                             // 'large' if px >= 24 || (px >= 18.66 && weight >= 700)
                             // else 'normal'. spec-pinned: design says "18.5px bold"
                             // in §8.0 and "18.66px bold" in §8.3 — 18.66 (the WCAG
                             // value) is the single threshold; weight >= 700 is the
                             // spec's reading of "bold" (design gives no number)
sameColor(c1, c2, eps=0.5)   // per-channel within eps
```

`color.test.js` vectors (design §12): every syntax above; W3C WCAG example
pairs (`#777777` vs `#ffffff` = 4.48, `#767676` vs `#ffffff` = 4.54, etc.);
`thresholdFor` full truth table **including the `nonText` channel —
`{nonText:true}` yields 3 even under prefersMore (M1; non-text UI never
uses 4.5/7)**; the known-bad `getSRGBLightness` counterexample (a color pair where the
shortcut disagrees with the linearized formula — assert our function follows
the linearized value); `deltaE2000` Sharma reference pairs; hue-bucket edge
vectors at 0/14.99/15/44.99/45/69.99/70/164.99/165/259.99/260/344.99/345 and
S=0.099/0.10.

## 4. `src/lib/classify.js` — fact → role (DOM-free)

### 4.1 Fact record (produced by `probe.js`, consumed here)

```js
Fact = {
  isRoot: boolean,              // documentElement or body
  tag: string,                  // lowercase
  type: string | null,          // input[type]
  ariaRole: string | null,      // [role] attribute
  display: string,              // computed display (block-level checks, §4.3 bg rule 6)
  attrs: {                       // only the keys the discriminators need
    popover: boolean, ariaModal: boolean, ariaInvalid: 'true'|'false'|null,
    ariaDisabled: boolean, ariaCurrent: string|null, dataSemantic: string|null,
    href: boolean,              // <a href> present (link detection)
  },
  background: { color: Color|null, hasImage: boolean, isGradient: boolean },
  border:    { widthPx: number, color: Color|null },   // widest visible side
  color:     Color | null,                             // computed text color
  fontSizePx: number, fontWeight: number,
  rect: { x, y, w, h }, viewport: { w, h },
  position: string,             // computed position keyword
  blendMode: string, filter: string, backdropFilter: string,
  isSvg: boolean, svgBBox: { w, h } | null,   // for fill/stroke geometry rule
  hasOurs: boolean,             // carries a data-uxx* attribute (contamination guard)
  visible: boolean,             // display≠none, visibility≠hidden, w>0, h>0
  isPlaceholder: boolean,       // ::placeholder source (special-cased, §6)
  hasOutlineFocus: boolean,     // outlineStyle≠none && outlineWidth>0 (focus rings)
  isFocused: boolean,           // element is document.activeElement (or inside it)
  inlineImportant: string[],    // properties whose INLINE declaration has
                                // !important (probe reads style attribute) —
                                // drives redirectInline, design §6
  isTopmost: boolean,           // overlay stacking proxy, §4.3 rule 4 (spec-pinned)
}
```

`Ctx = { pageLuminance: number, viewport: { w, h }, prefersMore: boolean,
onAccentSurface: boolean }`

- `pageLuminance` (**spec-pinned — round-3 M3**): `luminance(palette
  .backgrounds[0])` — the dominant (first) composite background from the §5
  aggregation (the same aggregation whose median drives the `appearance`
  verdict — it is the dominant sample, not the median sample itself). This is
  what rule 7 and the `button-secondary` row compare against; the content
  layer computes it once per pass from the DETECT stage. **Empty-list
  fallback (round-4 N3):** if `palette.backgrounds` is empty (skip-listed
  full-bleed canvas over a transparent body — probe yields nothing),
  `pageLuminance = luminance(resolveToken(['colors','background','default']))`;
  `palette.test.js` covers the empty-harvest case.

- `onAccentSurface` (**spec-pinned predicate — review F1/F6**; the content
  layer computes it against the *mapped* ancestor chain, excluding the
  element itself, because `classify` is DOM-free): `true` iff the nearest
  opaque mapped ancestor background role is `button-danger`, **or** the
  composited resolved background is chromatic (`toHsl(bg).s ≥ 0.35` and
  `hueBucket(bg) !== 'neutral'`) with `luminance(bg) ≥ 0.20`. These are the
  surfaces where design §7's `text-inverse` ("text on solid accent/button
  bg") is the correct foreground; neutral-dark buttons
  (`button-primary` L≈0.164, `button-secondary` L≈0.054) are excluded so
  their labels keep the light button-fg / rank tokens.

### 4.2 Signature

```js
classify(fact, ctx) → Assignment[]
// Assignment = { property: 'background'|'color'|'border'|'outline', role: Role,
//                sourceColor: Color, confidence: 0..1 }
// returns [] when the fact contributes nothing (skip list, design §6)
```

One fact yields up to four assignments (bg, text, border, outline) — evaluated
**per property**, with exactly one cross-property rule: `badge-*` (§4.3
background rule 4b) consults the already-computed color assignment.

### 4.3 Per-property rules (order matters — first match wins)

**background:**

1. Skip: `!fact.visible`; `fact.background.color == null`; `isTransparent`;
   `hasImage || isGradient` (design §6 — skip bg recolor, keep text/border);
   `fact.tag ∈ {img, canvas, video, iframe, frame, object, embed, input[type=image]}` (no marker at all);
   `fact.hasOurs` (contamination guard).
2. Root: `isRoot` **and** (top frame — caller sets `isRoot: false` in child
   frames, design §6 iframe row) → `page-background`.
3. `tag ∈ {input, select, textarea}` → `input-surface` — **spec-pinned
   carve-out (review F19):** `input[type ∈ {button,submit,reset}]` is routed
   to button detection instead (design §7.1's literal row lists `input` for
   `input-surface`; a submit button is a button by intent, and theming it as
   a form field would contradict §7's button rows).
4. Overlay: `position === 'fixed'` && covers ≥90% viewport (`rect.w*h ≥
   0.9*vp.w*vp.h`) && bg alpha ∈ (0,1) && `fact.isTopmost` → `overlay`.
   *spec-pinned (review F18):* `isTopmost` is probe's proxy for design §7.1's
   "top-most stacking context" — probe sets it when
   `doc.elementFromPoint(center)` returns the element or a descendant of it.
4b. **Badge (the cross-property rule):** if the color assignment (computed
   first — `classify` runs color rules before background rules) is a
   `semantic-*` role **and** the bg alpha ∈ (0, 0.45] (*spec-pinned* tint
   band; design §7 says "tinted bg" without numbers) → background assignment
   becomes `badge-<kind>` (e.g. `semantic-error` → `badge-error`) and the
   color assignment is rewritten to the same `badge-<kind>` (fg token). This
   is what keeps `badge-*` ROLE_RULES rows alive (E4 pairs, design §7).
5. `tag === 'dialog' || attrs.popover || ariaRole ∈ {dialog, menu, menubar,
   listbox, tooltip, combobox}` → `elevated`.
6. `tag === 'pre' || (tag === 'code' && fact.display !== 'inline')` →
   `code-surface` (block-level `code`; `display` is a Fact field, §4.1 —
   review F17).
7. Non-root container with own bg: `luminance(bg) < ctx.pageLuminance` →
   `surface-recessed`, else → `surface` (fallback, evaluated last — design §7.1).
8. Buttons are NOT backgrounds here: if the element is a button-ish element
   (§4.3 color rules), the background assignment is one of the `button-*`
   roles instead of 3–7. Order: button detection runs first for button-ish
   tags; see below.

**button detection — `detectButton(fact, ctx)`** (a single pure helper the
background rules run before rules 3–7, **and** which color rule 3 re-calls so
both channels agree; fires when `tag==='button'` or
`input[type ∈ {button,submit,reset}]` or `ariaRole==='button'`), on the
*page's* bg color (spec-pinned thresholds — design gives no numbers):

| condition (first match) | role |
|---|---|
| bg transparent/alpha 0 | `button-ghost` |
| `toHsl(bg).s ≥ 0.35` && hue ∈ [330,360) ∪ [0,20) (red/pink, covers Monokai `#f92672` at 338°) | `button-danger` |
| `s < 0.10` (neutral) && opaque && `|L(bg) − pageLuminance| ≤ 0.06` && `contrast(fg,bg) ≥ 3` | `button-secondary` |
| `s < 0.10` && opaque && `contrast(fg,bg) ≥ 3` | `button-primary` |
| otherwise | no bg assignment (leave page's button bg alone — never worse) |

**color (text):**

1. Skip: alpha 0; `hasOurs`; non-visible (`isPlaceholder` handled at 2).
2. `fact.isPlaceholder` → `text-muted` (design §6 — forced role, excluded from
   rank competition, token `colors.text.soft` by §7).
3. Button-ish element (`detectButton(fact, ctx) !== null` — the same pure
   detector the background rules call, so both channels agree without
   ordering dependence): color channel gets the same `button-*` role (fg
   token; E3 applies to `button-danger`). *spec-pinned:* design §7 defines
   `button-*.fg` rows but no label-detector; without this the fg rows are
   dead code (review F6-class defect, same shape as the old `focus` gap).
4. If `ctx.onAccentSurface` (§4.1 predicate) → `text-inverse` (direct).
   *spec-pinned:* runs **before** the semantic/hue detectors so every color
   on a bright chromatic surface (danger button, bright tint composites)
   diverts together — this is what makes the §6.3 universe enumeration
   cover all emit-able backgrounds.
5. Semantic detectors, in order (design §7 "ARIA/class/hue cues"):
   - `attrs.ariaInvalid === 'true'` → `semantic-error` (conf 0.9)
   - `ariaRole ∈ {alert, alertdialog}` → `semantic-error`; `ariaRole ∈
     {status, log}` → `semantic-info` (conf 0.8)
   - class-token cues — **only these roles may use class names** (design §7.1
     bans class guessing for surfaces, not semantic status):
     `/(^|[\s_-])(error|danger|invalid|failed|destructive)([\s_-]|$)/i` →
     `semantic-error`; `/(^|[\s_-])(warn|warning|caution)([\s_-]|$)/i` →
     `semantic-warning`; `/(^|[\s_-])(success|succeed|valid|confirmed|ok)([\s_-]|$)/i` → `semantic-success`;
     `/(^|[\s_-])(info|note|hint)([\s_-]|$)/i` → `semantic-info` (conf 0.7).
   - hue cue (§8.4), *spec-pinned* saturation floor `s ≥ 0.35` (review F4 —
     design defines only the `S < 0.10` neutral boundary; without a floor,
     near-neutral pastels would be promoted to semantic status): non-link
     text with `s ≥ 0.35` maps by `hueBucket` to the §8.4 target role
     (conf 0.6) — **every bucket is handled (review F3):**
     `red → semantic-error`, `orange → semantic-warning`,
     `green → semantic-success`, `cyan-blue → semantic-info`,
     `yellow → accent-yellow`, `purple-magenta → accent-magenta`.
     `neutral` does not promote (design §8.4's neutral target
     `colors.text.panel` is reached through the text rank pass, whose
     `text-secondary` row is exactly that token).
6. **Link:** `fact.attrs.href || ariaRole === 'link'` with a non-null text
   color → `link` (conf 0.85). *spec-pinned detector:* design §7 defines the
   `link` role but not its detector; anchors are links by meaning. Runs
   **before** the hue cue so §8.4's "accent-hued *non-link* text" holds.
7. `tag ∈ {code, pre}` → `code-text` (*spec-pinned*; keeps the `code-text`
   ROLE_RULES row alive; direct, excluded from rank — its token equals
   `text-primary`'s anyway).
8. Otherwise → ranked text: provisional role `text-primary`; the final text
   role is decided by the page-wide rank pass (§6.2 below). `classify`
   marks the assignment `ranked: true` so `map.js` knows to consult the rank
   table.

**outline:**

1. `fact.hasOutlineFocus` → `{ property: 'outline', role: 'focus' }`
   (spec-pinned, review F6: design §7's `focus` role = "outline/focus rings";
   this is its only assignment path — without it the role and its
   `outline-color` rule are dead code).

**border:**

1. Skip if `widthPx < 1` or color null/transparent/`hasOurs`.
2. `fact.isFocused && fact.border.widthPx ≥ 1` → `border-focus`

   border token; outline-drawn rings take the `focus` outline path above).
3. `fact.border.color` luminance vs page: contrast < 2.0 → `border-subtle`,
   else → `border` (spec-pinned threshold — design's rows describe "faint
   lines" vs "table/panel borders"; 2.0 is the discriminant).
4. `::selection` and `::placeholder` are pseudo rules, never element
   assignments.

Confidence values are informational (returned, not consumed in v1 — kept so a
future UI can show them; `map.js` ignores them).

`classify.test.js`: one vector per row of §7.1 + button table edges (s=0.34/0.35,

## 5. `src/lib/palette.js` — sample aggregation (DOM-free)

```js
aggregate(gridSamples, harvested, cssVars) → PagePalette
// gridSamples: [{ x, y, color: Color|null, skipped: boolean }]
//               (null color = miss/off-viewport/img hit — dropped, design §5)
// harvested:   { textColors: Color[], borderColors: Color[], linkColors: Color[],
//                accents: Color[], backgrounds: Color[] }   // already deduped
// cssVars:     { '--name': Color }  // only parseable ones reach here
PagePalette = {
  appearance: 'dark'|'light',
  backgrounds: Color[],   // alpha-composited over the sample stack, dominant first
  textColors: Color[], borderColors: Color[], linkColors: Color[],
  accents: Color[], cssVars: Record<string, Color>,
}
```

Rules:

- Grid sample colors composite **over what is beneath them in the sample
  stack** (top-down): a translucent hit composites over the previous opaque
  sample for that cell region (design §5 "(alpha-composited over the sample
  stack)").
- `appearance`: median luminance of composite backgrounds < 0.5 → `dark` else
  `light` (spec-pinned 0.5 — design says "light/dark verdict" without a
  number).
- Self-contamination guard: `aggregate` takes `harvested` already filtered by
  `probe` (skips `hasOurs`), **and** re-filters defensively: any harvested
  color equal to a known injected value (`#272822`, `#f8f8f2` when
  `appearance` would flip because of it) is dropped only if the element flag
  said so — the *element flag is authoritative* (spec-refinement: the guard
  lives in probe; palette.js exposes `isOurs(color, injectedValues)` used by
  tests, not in the hot path).
- Distinctness dedup: ΔE2000 ≤ 1 collapses (design §8.2 metric).

`palette.test.js`: translucent grid stack compositing; off-viewport/miss
drops; appearance boundary at median L=0.5; dedup by ΔE; harvested merge

## 6. `src/lib/map.js` — meaning → token color

### 6.1 Signatures

```js
// pure core (design §8.0):
map(fact, resolvedContext, palette, tokens) → { color, role, property, exception? }
// fact:            Assignment-shaped { property, role, sourceColor, sizeClass, ranked? }
// resolvedContext: { resolvedBgColor: Color,   // composited mapped bg the element sits on (§8.5)
//                    ancestorChain: Array<{ role, color, opaque }>,
//                    rankTable: Map<string, Role>,   // colorKey → final text role (§6.2)
//                    prefersMore: boolean }
//                  (round-3 m4: `onAccentSurface` was here but is unused — the
//                   divert happens in classify §4.1/§4.3, and §6.3's universe
//                   test ignores it; do not add it back)
// palette:         PagePalette (appearance + idempotence checks)
// tokens:          the generated pack (from tokens.js)

// cached page-level wrapper:
createMapper({ tokens, palette, prefersMore }) → {
  buildRankTable(assignments),   // run once after classify (§6.2)
  map(assignment, resolvedContext),
  stats(),                       // { hits, misses, exceptions } for tests
  clear(),
}
```

Cache key (design §8.0/§10): `(sourceColor, role, property, resolvedBgColor,
sizeClass)` — formatted as
`${fmt(src)}|${role}|${prop}|${fmt(resolvedBg)}|${sizeClass}`.

### 6.2 Text rank pass (`buildRankTable`)

Run **once per pass**, over all `ranked: true` text assignments (design §8.2):

1. Dedup distinct source colors: exact RGB equal, or ΔE2000 ≤ 1, collapse to
   one entry (keep the highest-confidence representative).
2. Sort sources by `luminance` descending. Tie resolution — design §8.2
   carries two conflicting clauses (review F2): "ties in luminance but
   distinct colors keep distinct ranks, ordered by hue as tiebreak" vs
   "equal source luminance ⇒ same token (collapse allowed)".
   **spec-refinement:** the distinct-ranks clause is operative — post-dedup
   distinct colors always keep distinct ranks, ordered by hue ascending for
   equal luminance; the collapse clause is read as *permitted, not required*,
   and we do not collapse (exact duplicates were already removed in step 1).
   Monotonicity (step 6) holds under either reading, so the design's intent —
   no inverted order — is preserved either way.
3. Rank → role: `rank 0 → text-primary`, `1 → text-secondary`,
   `2 → text-muted`, `≥3 → text-faint` (clamp — "dimmest excess → dimmest
   token", design §8.2). Never wrap, never invent.
4. The table maps `colorKey(fmt of source) → final role`; `map()` then
   resolves the role through `ROLE_RULES` (role→token stays §7's bijection).
5. Exclusions: `text-inverse`, `text-muted` from `isPlaceholder`,
   `semantic-*`, and `accent-*` assignments never enter the table (direct
   roles; `accent-*` has its own 2-token fallback pool, §6.3).
6. **Post-repair monotonicity:** after repair, for two sources s1 (brighter)
   and s2: `tokenLuminance(map(s1)) ≥ tokenLuminance(map(s2))`. Repair may
   collapse, never invert. Asserted in `map.test.js`, enforced by walking the
   pool in rank order (§6.3).

### 6.3 Repair (design §8.3)

**Pools:** `TEXT_RANK_ROLES` → `TEXT_RANK_POOL` (4 tokens);
`accent-yellow`/`accent-magenta` → `[colors.text.panel, colors.text.default]`
(design §8.3.6's neutral fallback for sub-threshold accent text — walking it
**changes the emitted role** to `text-secondary`/`text-primary`, i.e.
"converts colored text to neutral by design"; semantic roles are exempt and
keep hue). **`accent-*` is a multi-token pool — it is NOT part of the
single-token branch below** (review N1). Everything else
(link, focus, semantic-*, backgrounds, buttons, badges, text-inverse) is
single-token.

```
// M1: nonText channel — design §8.3.2's 3:1 applies to non-text UI, so
// border/outline emissions (border-focus, focus) never use 4.5/7.
nonText    = property ∈ { border, outline }
threshold  = thresholdFor({ sizeClass, muted: role ∈ {text-muted, text-faint} || isPlaceholder,
                            nonText, prefersMore })
// M2: background-property emissions have NO foreground pair — they are
// emitted surfaces, not fg/bg contrasts (design §7.2 constrains pairs only):
// a background is never contrast-checked, never walks a pool, and never
// sets exception. Token alpha is preserved; the §8.5 composite note applies
// to downstream fg checks AGAINST it, not to it.
// Reconciliation (round-4 N1): design §8.3.4's "all backgrounds" parenthetical
// is read as "no pool walk exists" — its failure⇒exception clause is
// inapplicable to background emissions (no fg pair exists to fail); design
// §7.2 and §12's three-state gate are pair-quantified and agree.
if property is a background → emit resolveToken(path) as-is; done.
emitted   = resolveToken(path for role/property)          // §7 direct
if contrast(compositedFg, resolvedBg) >= threshold → done
if pool(role).length > 1 → walk pool toward higher-contrast tokens:
     candidates ordered rank-adjacent first (from the element's own rank),
     then for accent text: text.panel → text.default (design §8.3.3);
     choose the first candidate meeting threshold; collapse-only (never a
     token that would invert §6.2 monotonicity). If the whole pool is walked
     and nothing meets threshold → **the design §7.2 multi-token residual**
     (review F1): keep `colors.text.default` — the pool's outermost token,
     which is also the highest-contrast member against every emit-able
     background — and set `exception: true`. Legality condition (design §7.2
     amended): a multi-token marker is legal **iff `emitted ===
     colors.text.default`** — repair did everything the pack allows. This
     reconciles design §8.3.4's single-token wording with §7.2's "everything
     else must repair, or carry the marker". (Under prefers-contrast: more
     this fires on most bright surfaces; in normal mode on the enumerated
     dark-pack surfaces such as `button-danger.bg` at 3.55:1 — the
     enumeration in `map.test.js` below is authoritative, not this note.)
else (single-token pool: link, focus, semantic-*, buttons,
      badges, text-inverse — NOT backgrounds (M2: they return above), NOT
      accent-*, see Pools above; review N1)
     → if isExcepted(...) → silent E1–E5
        else → keep pack value, set exception: true  (emitted as
               data-uxx-contrast="exception" by apply.js; §8.3.4)
```

Universe enumeration tests (`map.test.js`, review F1 — replaces round-1's
false superlative claims):

- **Universe:** every background `ROLE_RULES` can emit — opaque:
  `page-background`, `surface`, `surface-recessed`, `elevated`,
  `input-surface`, `code-surface`, `button-primary/secondary/danger.bg`;
  translucent composited over every opaque one: `overlay` (0.6),
  `selection.default` (0.5, design §8.5 lists it as chain-participating),
  `badge.*.bg` (0.15) — i.e. translucent-role-token × opaque-role-bg.
  Pack colors that are **not** role emissions (e.g. `colors.alpha.*`,
  raw `palette.*` accents) are out of universe: they can never be a
  `resolvedBgColor` (round-1 counterexample was out-of-universe).
- **Assertion (per pair × {normal, large} × {muted, not} × {prefersMore
  on/off} × text-pool/accent-pool roles):** §6.4's three-state property
  holds, and any multi-token marker satisfies `emitted ===
  colors.text.default`.
- **Backgrounds (M2):** emitting every background role over every opaque
  role-bg sets `exception` on none of them (backgrounds are surfaces, never
  fg/bg pairs — no contrast walk, no marker).
- **Border/outline (M1):** `border-focus` and `focus` vs `surface` and
  `elevated` pass under the 3:1 non-text threshold (4.06:1 and 3.59:1 —
  they would fail 4.5, so this pins the nonText channel end-to-end).
- **Arithmetic pins** (fail loudly if a token moves): `text.default` vs
  `button-primary.bg` = 4.60:1 (≥4.5 — normal mode passes, the binding case
  for the text pool); vs `button-danger.bg` = 3.55:1 (<4.5 → exhaustion →
  default+marker, normal mode); `selection.default` over `input-surface` =
  5.37:1 (passes 4.5, fails 7 → default+marker under prefersMore only).
- Rank text is additionally kept off the bright-chromatic surfaces by
  `classify`'s `onAccentSurface` divert (§4.1/§4.3) — that is a
  classification test, not an exemption here: `map.test.js` still runs the
  full universe directly.

`isExcepted(role, property, fg, bg)` implements design §7.2 exactly:

| E | predicate |
|---|---|
| E1 | `role ∈ {border, border-subtle}` (any bg) |
| E2 | `role ∈ {semantic-error, badge-error}` as **color** property vs any page-derived bg |
| E3 | `role === 'button-danger'` && property `color` (vs its own danger bg) |
| E4 | `role ∈ {badge-*}` color vs its own tinted bg (composite of tint over surface) |
| E5 | `role === 'text-faint'` (any bg) |

Note E2/E4/E5 make those pairs *silent* (no marker) — the marker state is
reachable from single-token pools outside E1–E5 (design §8.3.4) **and** from
the prefersMore text-pool exhaustion of §6.3 (design §7.2); those are the
only two doors.

Alpha compositing (§8.5) is the caller's job for the chain but `map` does the
local composite: `composite(emitted, resolvedBgColor)` before contrast, and
for translucent *sources* `composite(source, resolvedBgColor)` first.

Idempotence (§10 guard b): if `sourceColor` parses to **exactly** any value
present in the pack — including the translucent pack values
(`selection.default` 0.5, `badge.*` 0.15, `overlay` 0.6), compared parsed
with alpha (review F5: design says "already ∈ the pack" with no alpha
restriction; narrowing it to opaque-only would let re-probed badge/overlay
colors re-enter repair and oscillate) — the mapped color is the source
itself, short-circuiting rank/repair. This makes re-probing themed elements
converge.

### 6.4 The three-state assertion (design §12, map.test.js)

For every emitted pair exactly one holds:

1. `contrast ≥ threshold`, or
2. pair ∈ E1–E5 (silent), or
3. `exception === true` **and** the marker is legal — legal means one of:
   - the role's pool is single-token (design §8.3.4), **or**
   - the pool is multi-token **and** `emitted ===
     resolveToken(['colors','text','default'])` (design §7.2's exhausted-pool
     case — covers prefersMore text-pool exhaustion *and* accent-pool
     exhaustion; the accent walk's role conversion to `text-primary`/`text-secondary`
     is applied before this check).

Test property: `!(1) ⇒ (2 || 3-legal)` and `exception ⇒ 3-legal`, else fail.
Fixtures: seeded random source colors × roles × the §6.3 background universe
× both `prefersMore` settings.

Also asserted: every emitted color ∈ pack (parsed comparison, §7 invariant);
rank monotonicity (§6.2.6); idempotence (pack-in ⇒ pack-out); exhaustion
clamping (5 sources → 4 tokens, source #5 gets `text-faint`); hue-bucket
boundary vectors (in `color.test.js`, re-asserted through `map` for the
accent-text resolution path).

### 9.2 Autostart & testability


### 9.3 Pipeline (design §5, in order)

1. **Sync at document_start:** `injectBoot()`; then
   `runtime.sendMessage({ type: 'state', origin: location.origin })` with
   2000ms timeout (Promise.race).
   - reject/timeout → **fail open**: `teardown()` (removes boot), stop.
   - `{enabled:false}` or `{siteDisabled:true}` → teardown, stop (no
     observers, no probing).
2. **Wait** for `DOMContentLoaded` (or `readyState !== 'loading'`) **and**
   layout gate: `body.scrollHeight ≥ LAYOUT_MIN_PX && clientHeight ≥
   LAYOUT_MIN_PX && childElementCount > 0`. *spec-pinned (review F7):* poll
   every 50ms, cap 5000ms; on cap, proceed **without** the degraded marker —
   `data-uxx-degraded` is reserved for design §10's `MAX_ELEMENTS`/`TIME_TRIP`
   conditions. (Design §5 defines only the gate predicate; these poll numbers
   are the spec's.)
3. **Style cache lookup (design §15, spec §14) — exactly §14.5's order:**
   1. **Hoist, before any hash or walk** (all cheap; none depends on DETECT):
      `viewport` (`innerWidth`/`innerHeight`), `prefersMore`
      (`probe.prefersContrastMore()`), `prefersColorScheme`, `forcedColors`.
      `prefersColorScheme`/`forcedColors` are read through a guarded
      `matchMedia` helper — `typeof win.matchMedia !== 'function'` →
      `'light'`/`'none'` (the same guard `probe.prefersContrastMore` uses;
      review round-2 (a)).
   2. `lookupKey = computeKey({ url, vw, vh, prefersMore,
      prefersColorScheme, forcedColors, isTopFrame, version })` (§14.2) —
      **coarse: it carries no hashes.**
   3. `entry = await lookup(api, lookupKey)` raced against
      `CACHE_LOOKUP_TIMEOUT_MS`. This is the pipeline's **only** new `await`.
   4. **After** the await resolves: `walk = canonicalWalk(doc)` (no
      `readFact`) → `{ elements, indexOf, signature }`; **`domSig =
      walk.signature`**; `styleHash = styleSourceHash(doc)`. Both hashes are
      taken at this single point so signature and effects describe one
      DOM/CSS state (design §15.3).
   5. **Hit** (`validateEntry(entry, { lookupKey, version, styleHash,
      domSig })` is true — full field validation *before any replay*, §14.4):
      `ensureRoleSheet()` + `ensureInlineSheet()` → replay
      `mark`/`setException`/`redirectInline` from `entry.e` via
      `walk.elements[idx]`, inside a **try/catch: any throw →
      `apply.teardown()` + `apply.injectBoot()` + fall through to (6)**
      (restores the root inline style and purges every `data-uxx*`, so the
      subsequent harvest is clean) → restore `pal`, `rt = new Map(entry.rt)`,
      `bg`, `lum` → `session = buildSession(...)` (the helper shared with the
      miss path) → touch `t` (fire-and-forget) → return. **No `readFact`
      anywhere on this path.**
   6. **Miss / timeout / any `lookup` error / failed validation:** run steps
      4–7 below as today. During MAP+APPLY accumulate `effectRecords`
      (canonical idx via `walk.indexOf`, role ids actually passed to `mark`,
      exception flag, inline redirects). After step 7, if `!degraded`:
      `store()` carrying the **same** `styleHash`/`domSig` from (4) —
      fire-and-forget. Fail open throughout: the cache can only ever be
      skipped, never trusted.
4. **DETECT:** `withSheetsDisabled(sheets, () => { grid = sampleViewportGrid();
   harvested = walk + harvest; cssVars = collectCssVars(); })` →
   `palette = aggregate(...)`.
5. **CLASSIFY:** walk elements with the pinned recursive traversal
   (`forEachElement` order — document + open shadow roots, light children
   before shadow roots; *not* a `TreeWalker` — `TreeWalker` cannot cross
   shadow boundaries, review round-2 (e)),
   `readFact` → `classify(fact, ctx)`; stop at `MAX_ELEMENTS` or
   `TIME_TRIP_MS` (Date.now from pass start) → degraded mode
   (`setDegraded()`, only root + direct children themed).
6. **RANK:** `mapper.buildRankTable(allAssignments)`.
7. **MAP + APPLY, top-down:** depth-first from `documentElement`, maintaining
   `ancestorChain`; per element: compute `resolvedBgColor` by compositing the
   chain (root base = `#272822` in top frame; **child frames start with
   transparent base and skip the `page-background` root override** — design
   §6); map background first (append to chain), then color, then border, then
   outline; call `mark(el, role)` **once per non-null channel** (the multi-role
   union in §8 — a card can be `surface text-primary border-subtle focus`
   simultaneously; no dominant-role arbitration exists, round-3 B1);
   `redirectInline` when the element's own inline style
   declared the property with `!important` (probe flags
   `fact.inlineImportant`, §4.1);
   `setException` when `map` returns `exception`.
8. **Steady state:** MutationObserver on `documentElement`
   (`childList, subtree, attributes, attributeFilter: ['style','class']`),
   filtering: ignore mutations where `target`/`addedNodes` carry `data-uxx*`
   or attribute name starts with `data-uxx`. `--uxx-*` writes are suppressed
   by a **correctness check, not by the attribute filter** (review F9): our
   custom-prop writes go through `el.style.setProperty`, which mutates the
   `style` *attribute* and therefore *is* observed — so a `style`-attribute
   record is skipped when (i) the target carries any `data-uxx*` attribute,
   or (ii) `target.getAttribute('style')` contains `--uxx-`. Without (ii), a
   `--uxx-` write with no co-located marker would retrigger the loop.
   - rAF-batch: accumulate records; on rAF, process ≤ `FRAME_MAX_ELEMENTS`
     or `FRAME_BUDGET_MS`, remainder queued to next frame.
   - `records.length > RESCAN_THRESHOLD` → schedule whole-root rescan.
   - circuit breaker: `BREAKER_MUTATIONS` within `BREAKER_WINDOW_MS` →
     suspend for `BREAKER_BACKOFF_MS`.
   - teardown-loop guard: if teardowns attributable to our attribute writes
     hit `TEARDOWN_LIMIT` within 10s for a container → stop writing to that
     container (keep a `WeakSet` of suspended containers).
   - `document.hidden` → defer all work until `visibilitychange`.
9. **Teardown on disable message:** full `teardown()`, disconnect observer.

## 14. `src/content/cache.js` — style cache (design §15, spec-extension)

New module; slots into §9.3 step 3. No manifest change — `storage` is
already granted and MDN confirms content scripts share the key space with the
background ("the same set of key/value pairs are available to all scripts in
the background context and content scripts").

### 14.1 Constants (all named, design §15.1/§15.5)

```js
export const CACHE_SCHEMA = 'uxx-sc-v1';
export const CACHE_KEY_PREFIX = 'sc:';
export const CACHE_BUDGET_BYTES = 8 * 1024 * 1024;   // under the 10 MB default quota
export const CACHE_MAX_ENTRIES = 100;
export const CACHE_MAX_ENTRY_BYTES = 2 * 1024 * 1024;
export const CACHE_HASH_MAX_CHARS = 4_000_000;
export const CACHE_LOOKUP_TIMEOUT_MS = 250;
export const VIEWPORT_BUCKET_PX = 256;
```

There is deliberately **no `CACHE_INDEX_KEY`** — entries are self-describing
via `t`; concurrent tabs cannot orphan each other (design §15.5, review R5).

### 14.2 Key

```js
export function computeKey({ url, vw, vh, prefersMore,
                             prefersColorScheme, forcedColors,
                             isTopFrame, version })
  → `${CACHE_SCHEMA}|${version}|${url.length}:${url}`
    `|${Math.round(vw / VIEWPORT_BUCKET_PX)}|${Math.round(vh / VIEWPORT_BUCKET_PX)}`
    `|${prefersMore ? 1 : 0}|${prefersColorScheme}|${forcedColors}`
    `|${isTopFrame ? 1 : 0}`
```

`url = location.origin + location.pathname` (query + hash stripped).
`prefersColorScheme` = `'dark' | 'light'`; `forcedColors` = `'active' | 'none'`.
Both come from a **guarded `matchMedia` helper**: `typeof win.matchMedia !==
'function'` → `'light'` / `'none'` (the guard `probe.prefersContrastMore`
already uses; review round-2 (a)).
The hashes are **not** key components — they are validated fields (design
§15.1, review B1).

### 14.3 Hashing and the canonical walk

```js
export function fnv1a32(str, seed = 0x811c9dc5) → uint32   // pure, node-testable
export function hash64(str) → 16-hex string                // two seeds, folded

export function styleSourceHash(doc) → 16-hex string
// doc.styleSheets in order. Skip sheet iff ownerNode != null && ownerNode.hasAttribute('data-uxx').
// ownerNode == null (constructed/adoptedStyleSheets, review R2): hash (href||'') +
//   readable cssRules text, else a 'constructed' marker; never deref null ownerNode.
// inline (href == null, ownerNode present): hash ownerNode.textContent.
// external readable: href + '\n' + cssText per rule. SecurityError: href only.
// then documentElement.getAttribute('style'). Length-prefixed parts,
// CACHE_HASH_MAX_CHARS cap + truncation marker (design §15.2).

export function canonicalWalk(doc) → { elements: Element[], indexOf: Map, signature: string }
// Pinned order (design §15.3, review R7): documentElement is index 0 (null → empty).
// Per element: emit it, recurse LIGHT children in document order (each child before
//   its own subtree), THEN its open shadowRoot, THEN the next sibling. Per-element
//   pre-order, not level-order. NO pruning, NO readFact.
// signature = hash64 over, per element: tagNameLower + '#' + getAttribute('id') + '.' +
//   getAttribute('class') + '!' + getAttribute('style'). RAW attribute reads only —
//   never .className/.id/.style (SVGAnimatedString, review R1).
```

`forEachElement` (in `main.js:92`, exported as part of chunk D) is **exported**
so the order-parity test can compare the two traversals directly (chunk D).

### 14.4 Storage

```js
export function encodeEffects(records) → entry.e   // [idx, roleIds[], ex, [[propIdx, color]...]]
export function decodeEffects(entry)  → records
export function validateEntry(entry, { lookupKey, version, styleHash, domSig }) → boolean
  // s === CACHE_SCHEMA && k === lookupKey && v === version && degraded !== true
  // && sh === styleHash && ds === domSig && pal is object && rt is array
  // && bg/lum present && e is array of [number, number[], boolean, [number,string][]]
  // ANY failure → false, zero side effects (design §15.6 step 2, review R4)
export const ROLE_INDEX: Map<string, number>      // ROLE_RULES key order → 0..32
export const PROP_INDEX = { 'background-color': 0, 'color': 1 }

export async function lookup(api, lookupKey) → entry | null
// storage.local.get(CACHE_KEY_PREFIX + lookupKey) raced vs CACHE_LOOKUP_TIMEOUT_MS
// with a SETTLED FLAG: a resolution after timeout is discarded, never applied late
// (review R6). Timeout / error / absent → null.

export async function store(api, lookupKey, entry) → void
// get(null) → sum sc:* sizes → evict oldest-t entries past CACHE_BUDGET_BYTES /
// CACHE_MAX_ENTRIES (remove their keys) → skip if entry alone > CACHE_MAX_ENTRY_BYTES
// → set({['sc:'+lookupKey]: entry}). No index key. Rejection → one more LRU eviction
// + retry once, then give up. Caller treats it as fire-and-forget (design §15.5).
```

### 14.5 Integration (`main.js` §9.3 step 3)

After `waitUntilReady` + `isTopFrame`, **before** any hash or walk:

1. Hoist `viewport`, `prefersMore`, `prefersColorScheme`, `forcedColors`
   (all cheap; none depends on DETECT). The two media-query reads go through
   the guarded helper (§14.2): no `matchMedia` → `'light'` / `'none'`.
2. `lookupKey = computeKey({ url, vw, vh, prefersMore, prefersColorScheme,
   forcedColors, isTopFrame, version })`.
3. `entry = await lookup(api, lookupKey)`.
4. **After** the await: `walk = canonicalWalk(doc)`; `domSig =
   walk.signature`; `styleHash = styleSourceHash(doc)`.
5. **Hit** (`validateEntry(...)` true): `ensureRoleSheet()` +
   `ensureInlineSheet()`; replay `mark`/`setException`/`redirectInline` from
   `entry.e` via `walk.elements[idx]` inside a try/catch (throw →
   `apply.teardown()` + `apply.injectBoot()` + fall through to step 6);
   restore `pal`/`rt = new Map(entry.rt)`/`bg`/`lum`; `session =
   buildSession(...)`; touch `t`; return. **No `readFact` anywhere.**
6. **Miss:** run steps 4–7 (DETECT → CLASSIFY → RANK → MAP+APPLY) as today.
   During MAP+APPLY accumulate `effectRecords` (canonical idx via
   `walk.indexOf`, role ids actually passed to `mark`, exception flag, inline
   redirects). After step 7, if `!degraded`: `store()` — fire-and-forget,
   carrying the **same** `styleHash`/`domSig` captured in step 4.

`buildSession` is **extracted** from `runPipeline`'s tail and shared by the
hit and miss paths so the session shape (`suspended`, `teardowns`, `rescanAll`,
`applyElement` with `rankTable`-per-call binding) is byte-identical (review
R8). `api` is the injected `getApi()` result; tests inject a fake
`storage.local`.

### 14.6 Tests (canonical list; §11 points here)

`tests/cache.test.js` (jsdom), covering design §15:

- `fnv1a32`/`hash64`: determinism + avalanche (different input → different hash).
- `styleSourceHash`: inline `<style>` text change → new hash; `data-uxx`-owned
  sheets excluded (inject a boot sheet → hash unchanged); cross-origin
  (`cssRules` throws) → href-only; **`ownerNode == null` constructed sheet →
  hashed without throwing** (R2); `CACHE_HASH_MAX_CHARS` cap + marker.
- `canonicalWalk`: **order parity with the exported `forEachElement`** (same
  element sequence for the un-pruned case); shadow-root position (host's light
  subtree before its shadow, before the host's next sibling); `documentElement`
  = index 0; signature changes on class change **via `getAttribute` on an SVG
  element** (R1), on style change, on id change, on element insert.
- `computeKey`: each component (version/url/bucket/pm/colorScheme/forcedColors/
  isTopFrame) flips the key; bucket boundary — `Math.round(vw / 256)` flips at
  **127→128** (0.496→0.5 rounds to 0→1) and **383→384** (1.496→1.5 → 1→2); a
  255→256 assertion would *not* flip (both round to 1) and must not be used.
- `encodeEffects`/`decodeEffects`: round-trip incl. empty-effect omission.
- `lookup`: **settled-flag discard** (resolve after timeout → null, never a
  late hit — R6).
- `store`: LRU eviction by oldest `t`; budget enforcement; `CACHE_MAX_ENTRY_BYTES`
  skip; no-index coherence (two stores, no orphan).
- `validateEntry`: each field mismatch → false with **zero side effects**
  (no attribute written); malformed `e` record → false (R4).
- **main integration (the load-bearing case):** run `runPipeline` twice against
  an identical jsdom document with a fake `storage.local`. First run populates
  the cache. Second run: assert **zero `readFact` calls AND zero
  `sampleViewportGrid` calls** (spy both — the design claims zero
  computed-style/layout reads), and that the resulting `data-uxx-role`
  attributes, `data-uxx-contrast`, and `--uxx-inline-*` writes are
  **byte-identical** to the first run's. Then: change a class → assert miss →
  full pipeline re-runs; a degraded run (`MAX_ELEMENTS` forced) → assert
  nothing cached; **mutate a ranked-text element after a hit → assert the
  rank-corrected role from the restored `rt`** (R8 regression).
